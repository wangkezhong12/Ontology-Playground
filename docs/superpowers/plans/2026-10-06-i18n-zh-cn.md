# UI i18n zh-CN Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Localize all user-facing UI strings (plus quests / quest generator / designer templates) to Chinese with a 中/EN toggle, per the approved spec at `docs/superpowers/specs/2026-10-06-ui-i18n-zh-cn-design.md`.

**Architecture:** New `src/i18n/` module (en.ts `as const` + zh-CN.ts dictionaries + overloaded `t()`), language state on the existing Zustand `appStore` (mirrors the theme persistence pattern), mechanical `t()` wrapping in ~30 component files. zh→en→fallback→key resolution; static keys are compile-time checked; data-driven keys (quests, templates) require a mandatory English fallback. Chinese is the default; a Header toggle switches to English; choice persists in `localStorage['language']`.

**Tech Stack:** React 19, TypeScript 5.9 (strict), Zustand 5, Vite 8, Vitest 4 + Testing Library (jsdom).

## Global conventions (apply to every task)

### t() usage patterns

```tsx
import { useI18n } from '../i18n';            // React components (re-renders on toggle)
const { t } = useI18n();

// JSX text
<span>{t('header.summary')}</span>

// Attributes (placeholder / title / data-tooltip / aria-label)
<input placeholder={t('designer.entityName')} />
<button aria-label={t('header.about')} data-tooltip={t('header.about')}>

// Interpolation
<span>{t('quest.earnedBadges', { count: earnedBadges.length })}</span>

// Non-React modules (data files, stores, lib):
import { t } from '../i18n';
const msg = t('questGen.clickEntity', { name: entity.name });
```

### Key naming

- Static UI keys: `<area>.<name>` camelCase — areas: `common`, `header`, `stats`, `inspector`, `pathfinder`, `search`, `query`, `quest`, `questGen`, `designer`, `learn`, `modal.<name>`, `tour`, `palette`, `embed`, `footer`, `graph`, `toast`, `test`.
- Data-driven keys (overload 2, mandatory fallback): `quest.<id>.title|description|hint`, `quest.<id>.step.<stepId>.instruction`, `template.<id>.label|description`.
- en.ts is the complete static key set; zh-CN.ts may be partial (missing keys fall back to en at runtime).

Create `src/i18n/index.ts`:

```ts
import { useAppStore } from '../store/appStore';
import type { LanguageId } from '../store/appStore';
import { en } from './en';
import { zhCN } from './zh-CN';

export type { LanguageId };
export type StaticKey = keyof typeof en;
export type Vars = Record<string, string | number>;

function interpolate(template: string, vars?: Vars): string {
  if (!vars) return template;
  return template.replace(/\{(\w+)\}/g, (match, name: string) =>
    name in vars ? String(vars[name]) : match
  );
}

/**
 * Resolve a key. Language is read from the store singleton AT CALL TIME —
 * never at module evaluation. This will matter once questGenerator imports
 * t() (Chunk 4), forming the cycle appStore → questGenerator → i18n →
 * appStore — benign while all reads stay deferred to call time.
 */
function lookup(key: string, fallback?: string): string {
  const lang = useAppStore.getState().language;
  if (lang === 'zh-CN') {
    const zh = zhCN[key];
    if (typeof zh === 'string') return zh;
  }
  const english = en[key as StaticKey];
  if (typeof english === 'string') return english;
  return fallback ?? key;
}

// Overload 1 — static keys, compile-time checked.
export function t(key: StaticKey, vars?: Vars): string;
// Overload 2 — data-driven keys; fallback is REQUIRED and holds the English
// text from the data file (quests, templates).
export function t(key: string, vars: Vars | undefined, fallback: string): string;
export function t(key: string, vars?: Vars, fallback?: string): string {
  return interpolate(lookup(key, fallback), vars);
}

export function useI18n() {
  const language = useAppStore((s) => s.language);
  const setLanguage = useAppStore((s) => s.setLanguage);
  return { t, language, setLanguage };
}
```
